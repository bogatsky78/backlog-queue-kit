# Комплект: проєктні дані

> **Заготовка.** Її створює `install.sh` і **штампує в неї шлях** нижче. Скіл
> `kit` посилається сюди по фіксованому шляху; оновлення комплекту цей файл не
> чіпає, тож правити його на місці — норма.

## Де лежить комплект

`__KIT_PATH__`

Це та тека, у якій правиться механіка. Копія в цьому проєкті — результат
`install.sh`, а не місце для правок: змінений на місці файл комплекту
`--update` затирати відмовиться й назве поіменно.

## Предметні слова для грепа перед комітом у комплект

Комплект публічний, і ризик — витік предметного **з** проєкту, а не читання
комплекту. Перед кожним комітом туди прогнати цей список; порожній результат —
частина роботи.

- *(приклад)* назва проєкту й продукту;
- *(приклад)* назви технологій і сутностей, специфічних для предметної області;
- *(приклад)* імена файлів даних і довідників.

```bash
grep -rniE '<слово>|<слово>|…' --exclude-dir=.git <комплект>/
```

## Місцеві відхилення

Файли комплекту, які тут навмисно відрізняються від нього, і чому. Порожній
розділ — найкращий стан: він означає, що `--update` каже «нічого змінювати».

- *(приклад)* немає жодного.
