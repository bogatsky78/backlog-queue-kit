# queue-kit — черга задач на Backlog.md, готова до перенесення

Комплект, який ставить у проєкт чергу задач: **скіл, гачок, п'ять команд і
обгортку CLI**. Двигун — [Backlog.md](https://github.com/MrLesk/Backlog.md)
(MIT, TypeScript), закріплений на теґу **v1.50.1**.

Сам двигун тут не лежить. Клон один на машину — за замовчуванням
`/data/backlog.md`, — і всі проєкти користуються ним спільно.

```bash
# один раз на машину
git clone --branch v1.50.1 --depth 1 https://github.com/MrLesk/Backlog.md.git /data/backlog.md
cd /data/backlog.md && bun install --frozen-lockfile --omit=optional

# на кожен проєкт
./install.sh /шлях/до/проєкту
```

Клон двигуна за замовчуванням очікується в `/data/backlog.md`. Інший шлях —
змінна `BACKLOG_MD_HOME`, її розуміють і `install.sh`, і `bin/backlog`.

Далі встановлювач сам скаже три кроки, яких не робить: `backlog init`, два ключі
в `config.yml` і заповнення `.claude/queue-project.md`.

## Що всередині

| Файл | Роль |
|---|---|
| `template/bin/backlog` | обгортка: знаходить корінь проєкту сама, звіряє теґ двигуна, відмовляється працювати, якщо клон із нього з'їхав |
| `template/.claude/skills/queue/SKILL.md` | **правила** — таблиця «ситуація → команда», чотири черги, що в яку секцію, робота з агентами. Універсальний, без згадок будь-якого проєкту |
| `template/.claude/hooks/enforce-queue-cli.py` | не дає правити `backlog/` руками й не пускає задачу в `In Progress` з невирішеними `[NEEDS CLARIFICATION]` |
| `template/.claude/hooks/enforce-queue-cli.test.py` | 55 випадків. Прогонити після кожної правки гачка |
| `template/.claude/commands/queue*.md` | `/queue`, `/queue-main`, `/queue-future`, `/queue-done`, `/queue-history` — вивід підставляється в промпт напряму |
| `template/.claude/queue-project.md` | **заготовка під проєктне.** Скіл посилається сюди по фіксованому шляху |
| `snippets/settings.json` | дозвіл `Bash(bin/backlog:*)` і реєстрація гачка через `$CLAUDE_PROJECT_DIR` |
| `snippets/config.yml` | `statuses` і `definition_of_done` — два ключі, яких `config set` не приймає |
| `install.sh` | копіює шаблон, зливає `settings.json`, дописує `.gitignore`. Наявних файлів не перезаписує |

**Межа між скілом і проєктним файлом.** У скілі — механіка Backlog.md і принципи
роботи з агентами; у `queue-project.md` — рішення власника, чого в цьому проєкті
не делегують, куди йде багатослівний вивід, де живуть довгі плани. Скіл
переносний як є; проєктний файл щоразу новий.

## Чому CLI, а не MCP

Backlog.md пропонує обидва шляхи. Причина технічна: у Claude Code plan mode
гальмує немутуючі MCP-виклики (гілка вимагає `e.mcpInfo && !e.isReadOnly`), а
вбудований `Bash` іде звичайними правилами дозволів. Через MCP запис у чергу з
plan mode просив би підтвердження на кожну дію; через CLI — ні. Перевірено
читанням бінарника Claude Code 2.1.232: plan mode обмежує запис рівно у двох
місцях, і `Bash` не підпадає під жодне.

## Чому з джерел, а не бінарником

`npm i -g backlog.md` тягне standalone-бінарник на **~101 МБ** — це вшитий
рантайм Bun, непрозорий і неправний. Запуск із джерел (`bun src/cli.ts`) дає
той самий CLI, який можна прочитати.

Ціна: `bun install` ставить **533 пакети, 442 МБ** devDependencies (React,
Tailwind, mermaid — усе під веб-UI). Продакшн-залежностей у пакеті справді нуль,
але «нуль залежностей» стосується лише прода. `--omit=optional` прибирає шість
платформних бінарників і знімає 485 МБ із 927.

Docker не беремо: офіційного образу немає, і форма не та — це CLI, що чіпає
файли робочого дерева кілька разів на хід, а контейнер додав би `docker run` на
кожен виклик, бінд-маунт і зіставлення uid/gid.

## Що варто знати про Backlog.md v1.50.1

Дороге знання. Усе перевірено на живому CLI, не з документації.

**Чужі ключі у frontmatter не виживають.** `task edit` перезаписує frontmatter із
власної моделі й **мовчки викидає** все, чого не знає. Тіло markdown при цьому
виживає дослівно, включно з власними секціями. Тобто: машинні позначки — у
`labels` (приймають довільні рядки з `:` і не-латиницею), довгий текст — у тіло,
своїх ключів у frontmatter не заводити ніколи.

**Ручний порядок є штатно.** Поле `ordinal`: `--ordinal N` при створенні й
редагуванні, `task list --sort ordinal`, є в `--json`. Задачі без нього йдуть у
хвіст. Номери ставити розріджено (10, 20, 30).

**`Done` не архівують.** `task archive` відмовляє задачі в термінальному статусі:
«Done tasks should be completed, not archived». Історія — це `task complete` →
тека `backlog/completed/`; задача випадає зі списків **і з пошуку**, але
`task view <id>` її читає. `task archive` означає «вирішили не робити» — така
задача зникає зовсім.

**Документи й рішення наповнюються лише руками.** `doc create` і
`decision create` беруть **тільки заголовок** — прапорця на вміст немає, і жодна
наступна команда тіла не переписує. Дописане руками виживає й індексується
пошуком. Тому гачок пропускає `backlog/docs/` і `backlog/decisions/`: інакше
обидві сутності непридатні.

**`config set` відмовляє двом ключам** — `statuses` і `definition_of_done`
(«cannot be set directly»). Правити в `config.yml`. І при **кожному** записі
конфіга CLI **викидає з файлу всі YAML-коментарі**, тому пояснення до
налаштувань там не тримати.

**ID чернетки тимчасовий.** `DRAFT-1` при `draft promote` стає наступним вільним
номером у просторі задач (`DRAFT-1` → `TASK-6`).

**Підзадачі ієрархічні:** `task create -p TASK-2` дає `TASK-2.1`. Будь-який код,
що розбирає ID, мусить це вміти — номер не `\d+`. На цьому гачок уже горів:
шаблон із голим `\d+` тихо не спрацьовував на підзадачах, тобто рівно там, де
лежить детальна робота.

**`init` дописує в `CLAUDE.md`, не переписує** — блок між маркерами
`<!-- BACKLOG.MD GUIDELINES START/END -->`, наявний текст не чіпає. Але блок
англійський і велить бігати `backlog instructions overview` **перед кожним
запитом** — чистий видаток контексту. Тому `--agent-instructions none`.

**`priorities` — три рівні** (`High`/`Medium`/`Low`), не п'ять.

**`auto_commit: false` — дефолт, і його треба зберегти**, якщо коміти в проєкті
робить окремий агент або людина.

## Пастка, на якій гачок горів двічі

Обидві знайшлись лише тому, що гачок прогнали на **справжній** черзі з трьох
десятків файлів, а не на вигаданих фікстурах:

1. **DoD цитує маркер дослівно.** Пункт `definition_of_done` про
   `[NEEDS CLARIFICATION: ...]` CLI штампує в **кожну** задачу — і гачок,
   грепаючи файл, читав власний чекліст і відмовляв **усім** задачам проєкту.
   Лікування: згенеровані блоки (`<!-- DOD:BEGIN -->`,
   `<!-- ACCEPTANCE_CRITERIA:BEGIN -->`) зі сканування виключені.
2. **Ієрархічні ID.** Див. вище.

Тому в тестах обидві регресії закриті окремими випадками, а чиста задача у
фікстурі несе **справжню** DoD-заготовку.

## Залежність, про яку варто знати

Гачок імпортує **сегментатор командного рядка** з
`~/.claude/hooks/enforce-repo-agent.py` — щоб не тримати другу копію розбору
лапок, `$(...)`, heredoc-ів і обгорток. Якщо того файла немає, гачок **не
падає**: shell-перевірки вимикаються, гілка `Write`/`Edit` (та, заради якої він
і писаний) працює, причина пишеться в `.claude/hooks/enforce-queue-cli.error.log`.

Якщо переносите комплект на машину без цього гачка — або покладіть його туди,
або вбудуйте сегментатор у `enforce-queue-cli.py`.

## Веб-UI

`bin/backlog browser` — дошка, картки задач, пошук. Слухає **лише `127.0.0.1`**
(порт 6420 за замовчуванням), назовні нічого не світиться. Для постійної роботи
простіше юнітом systemd, ніж контейнером.
